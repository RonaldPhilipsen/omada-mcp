# omada-mcp Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A configurable Go MCP server wrapping the Omada OpenAPI (generated northbound client from `github.com/RonaldPhilipsen/omada`), shipped as a container image to ghcr for ToolHive.

**Architecture:** Single binary, env-configured. `internal/mcpkit` is the MCP plumbing (server build, registration, read-only + group gating, arg/result helpers). `internal/omadaclient` wraps `cloud.New` (on-prem client-credentials mode) and adds envelope decoding. Curated tools live in `internal/tools/<group>.go`; a generic `ops_lookup`/`ops_call` escape hatch over a checked-in, spec-fingerprint-verified operation index; wire-up in `internal/wire` + `cmd/omada-mcp`.

**Tech Stack:** Go 1.27.3, official `github.com/modelcontextprotocol/go-sdk`, `github.com/RonaldPhilipsen/omada` (generated northbound client + auth transport), multi-stage Docker build.

**Spec:** `docs/superpowers/specs/2026-11-02-omada-mcp-design.md`

## Global Constraints

- Module path: `github.com/RonaldPhilipsen/omada-mcp`. Go version matches the `omada` module: `go 1.27.3`.
- Dependencies: pinned `github.com/modelcontextprotocol/go-sdk` (latest at scaffold time; Renovate bumps later) and `github.com/RonaldPhilipsen/omada@v0.2.0` (task 11 creates that tag; until then `v0.1.0`).
- Auth is exclusively `cloud.New` on-prem mode: `BaseURL`, `OmadacID`, `ClientID`, `ClientSecret` — never username/password. Never reimplement token auth.
- Env vars, exact names and defaults: `OMADA_BASE_URL` (required), `OMADA_CLIENT_ID` (required), `OMADA_CLIENT_SECRET` (required), `OMADA_OMADAC_ID` (required), `OMADA_INSECURE_TLS` (default `false`, `true` enables), `OMADA_READ_ONLY` (default `true`; only the literal string `false` allows writes), `OMADA_TOOL_GROUPS` (default all groups), `OMADA_ENABLE_DISPATCH` (default `false`, literal `true` enables), `OMADA_TRANSPORT` (`streamable-http` default | `stdio`), `OMADA_PORT` (default `8080`, streamable-http only).
- Read-only gating happens at registration: mutating tools are never listed when read-only.
- Envelope contract: HTTP 200 with non-zero `errorCode` ⇒ `*cloud.APIError` (the `cloud` package's envelope pattern); every tool converts that into an MCP tool error carrying code and message.
- All tests run as `go test ./... -race -count=1`. Distroless/static final image; build `-trimpath -ldflags "-s -w"`; `CGO_ENABLED=0`.
- Image: `ghcr.io/ronaldphilipsen/omada-mcp`, tags `v*` semver + `latest`, platforms `linux/amd64` + `linux/arm64`.
- Generated-code fingerprint: `gen/genopsindex.py` fetches the spec live and asserts its SHA-256 equals the value in `gen/data/spec.sha256` (a checked-in copy of `omada`'s `gen/spec.sha256`); mismatch exits non-zero.
- SDK divergence rule: this plan pins *local* interfaces exactly; the official SDK's exact function/var names at the pinned version may differ slightly from the calls shown here (written at an assumed v1). The implementer must use the pinned SDK's equivalent (e.g. in-memory transport pair, streamable HTTP handler constructor, typed result accessors), keeping the local API identical, and verify equivalence via the Task 1 tests before continuing.

## Review Focus

1. **Secret leakage** — `OMADA_CLIENT_SECRET`, tokens, or password-shaped strings in tool results, errors, or logs. Owner: task 3 (test asserts error/result bodies never contain the secret or token).
2. **Read-only bypass** — a mutating call reaching the controller while configured read-only, via a curated tool or `ops_call`. Owners: task 1 (mutating tools hidden at registration), task 12 (`ops_call` rejects a mutating operation with a read-only tool error).
3. **Envelope business errors passed through raw** — HTTP 200 with `errorCode != 0` should map to a clean `*cloud.APIError` and a tool error with code + message, never a decoded-into-result of a nil payload. Owners: task 3 (DoEnvelope unit test), task 4 (site group tool-error test).
4. **Zero-value arg defaults** — omitted `page`/`pageSize` must default to 1/20 sent to the controller, omitted `omadac_id` must fall back to `OMADA_OMADAC_ID`, missing required ids must fail validation before any HTTP call. Owner: task 4.
5. **Auth failures surfacing as crashes or hangs** — token endpoint failure on startup leads to clean construction error; expired-token 401 returns one retry then a clean error (retry itself is `omada`'s behavior; we only assert propagation). Owner: task 3.

  func JSONResult(v any) (*mcp.CallToolResult, error) // v marshaled as JSON text content

### Task 12: `internal/tools/dispatch.go` (escape hatch)

**Files:** Create: `internal/tools/dispatch.go`, `dispatch_test.go`. group `""` (always present when enabled).

**Interfaces:**
- Consumes: `opsindex`, `omadaclient.Client.HTTPClient()`, `BaseURL()`, `OmadacID()`, config.ReadOnly.
- Produces:
  ```go
  func OpsLookup() mcpkit.Tool
  func OpsCall() mcpkit.Tool
  ```
  ```go
  type OpsLookupIn struct {
      Keyword string `json:"keyword,omitempty"`
      Tag     string `json:"tag,omitempty"`
      Limit   int    `json:"limit,omitempty"` // default 10, cap 50
  }
  type OpsCallIn struct {
      OperationID string            `json:"operation_id"`   // required
      PathParams  map[string]string `json:"path_params,omitempty"`
      Query       map[string]string `json:"query,omitempty"`
      Body        json.RawMessage   `json:"body,omitempty"`
  }
  ```
  `ops_lookup` semantics: case-insensitive substring across `id`, `summary`, and `tag`; `tag` filter narrows exclusively; results ordered by `id`; each hit carries `{id, method, path, tag, summary, mutating}`. `ops_call` semantics: fill `{omadacId}` from `path_params` or default `OmadacID()`; every remaining `{curly}` in the path must be `path_params`-supplied or error naming them; unknown `operation_id` → tool error; **with `ReadOnly=true`, an op with `Mutating=true` is rejected with a tool error whose text contains both "read-only" and the operation id** (Review Focus 2). Response: on 2xx return status code + decoded envelope `result` via `omadaclient.Envelope`; on APIError return tool error with code + message.

  1. `ops_lookup` keyword "site" finds at least the site-list op and a wired `Tags` filter narrows correctly.
